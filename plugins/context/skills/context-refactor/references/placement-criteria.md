# 配置基準

記述ごとに「いつ読み込まれるべきか」「守られる保証が要るか」で置き場所を決める。

## 判定の順序

```text
for each 記述:
  if 毎回例外なく守らせたい決定的な処理（禁止コマンド、生成物の再生成、書式チェック）:
    → hook または lint ルール。AGENTS.md の指示は助言でしかなく守られる保証がない
  elif 複数ステップの手順、または一部の作業でしか使わない知識:
    → skill（手順・テンプレート・スクリプトを同じディレクトリにまとめる）
  elif 特定のディレクトリのコードにだけ効く規約:
    if そのディレクトリに閉じている:
      → そのディレクトリの AGENTS.md（コロケーション）
    else（複数ディレクトリにまたがる、glob で表せる）:
      → `.claude/rules/<topic>.md` に `paths:` frontmatter を付けた path-scoped rule
  elif 人間の読者向け（概要、インストール、ライセンス、リンク）:
    → README.md
  elif コードや設定を読めば分かる（ディレクトリ構成、依存一覧、技術スタック、ファイル単位の説明）:
    → 削除
  elif 消しても Claude が間違えない一般論:
    → 削除
  else:
    → ルートの AGENTS.md に残す
```

## コロケーション

ディレクトリ固有の規約は、`.claude/rules/` よりそのディレクトリの AGENTS.md に置く。実装の隣にあるので変更時に更新漏れが起きにくく、そのディレクトリのファイルを読んだときに自動で読み込まれる。

サブディレクトリの AGENTS.md が自動で読み込まれるのは、作業ディレクトリとその上位に `CLAUDE.md` / `.claude/CLAUDE.md` / `CLAUDE.local.md` が 1 つも無いときだけである。しかも Read ツールでそのディレクトリのファイルを開いたときに限られる。ルートに CLAUDE.md（`@AGENTS.md` の import や AGENTS.md への symlink を含む）を残す場合は、サブディレクトリにも同じ形の CLAUDE.md を置く。置かないと、既定の設定ではサブディレクトリの AGENTS.md が読まれない。

`.claude/rules/` が向くのは次の場合。

- プロジェクト全体に効くが、AGENTS.md に置くと長くなるもの（例: サンプルコード付きのコーディング規約）
- 複数ディレクトリにまたがり、`paths:` の glob で対象を表せるもの

## ルート AGENTS.md に残すもの

毎セッション読み込まれるので、各行について「消したら Claude が間違えるか」を問い、間違えないものは置かない。200 行未満を目安にする。

- プロジェクトの目的（2〜3 文）
- 日常的に使うコマンド（build / test / lint / typecheck の正確な呼び方）
- このリポジトリ固有の規約と、コードからは読み取れない落とし穴
- 作業の種類ごとの参照先（「X をするときは Y を読む」というポインタ）
- 守られないと困る禁止事項（可能なら lint ルールや hook の名前を添える）

## サブディレクトリの AGENTS.md に置くもの

- そのパッケージ固有の開発コマンド、環境変数、注意点
- ルートと重複する記述は書かない

## README.md

人間向けの入口。プロジェクト名と 1 行説明、概要、最小限のインストール手順、よく使うコマンド、関連リンク、ライセンス。AI 向けの規約や詳細な構成は書かない。monorepo では npm へ公開するパッケージごとに置く。

## 言語

対象プロジェクトの既存ドキュメントの言語に合わせる。
