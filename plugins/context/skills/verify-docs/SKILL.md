# verify-docs

ドキュメントの事実主張を、コードベースと一次情報で裏付けが取れるかで判定する。もっともらしさや記憶ではなく、見つけた証拠（ファイルと行、コマンド出力、URL）で判定する。

## 引数

- `file-path`: 対象の Markdown。省略時はプロジェクトの `**/AGENTS.md`、`**/CLAUDE.md`、`.claude/rules/**/*.md` を順に処理する。README や `docs/` 配下はファイルを指定されたときだけ対象にする
- `--fix`: すべての修正案を適用してから報告する
- `--review`: 変更のあるセクションごとにユーザーの承認を取ってから適用する
- どちらもない場合は、依頼の文面で決める。「直して」「更新して」のように修正を頼まれていれば `--fix` と同じにし、「正しいか」「確認して」のように確認だけを頼まれていれば修正案の提示で止めてファイルは変更しない。依頼の範囲を超えて書き換えないため

## 手順

1. ファイルを見出し（`#` / `##` / `###`）で分け、各セクションの開始行・終了行を記録する
   - YAML frontmatter はセクションとして扱わず、そのまま残す
   - コードブロック内の `#` は見出しではない
2. セクションごとに検証できる主張を抽出する。何を主張とみなすかは [claim-extraction-patterns.md](references/claim-extraction-patterns.md) に従う。一覧が全件だという暗黙の主張も含める
3. 主張を検証し、判定を付ける
   - VERIFIED: 証拠が主張を裏付ける
   - FALSE: 証拠が主張と食い違う
   - OUTDATED: 以前は正しかったが現状と合わない
   - UNVERIFIED: どちらの証拠も見つからない
   - リポジトリ内の主張は Grep / Glob / Read とコマンド実行で、外部ツールやバージョンの主張は WebSearch / WebFetch で確かめる
   - `@path` の import は参照先の存在だけを確かめ、中身は展開しない
4. FALSE と OUTDATED の主張について、セクションの修正案を作る。UNVERIFIED は変更しない
5. モードに従って修正を扱う

   ```pseudocode
   if --review:
     修正案のあるセクションだけを AskUserQuestion で「適用 / 修正して適用 / 変更しない」から選んでもらう（1 回に最大 4 問）
     選ばれたものを適用する
   elif --fix or 依頼が修正を求めている:
     すべての修正案を適用する
   else:
     適用しない（報告に修正案を含める）
   ```

   置換はセクションの終了行の降順で行う。前から置換すると後続セクションの行番号がずれるため

6. 報告する。全主張について「判定・主張・証拠・修正案（適用した場合はその旨）」を箇条書きで出す。UNVERIFIED は確認できなかった理由も書く

## 大きい文書の分担

検証は既定ではこのセッションが行う。検証するセクションが 10 を超える文書だけ、セクション群をサブエージェントに分担させる。同時に起動するのは 4 体までにする。サブエージェントには対象セクションの本文・行範囲・抽出した主張・上記の判定基準を渡し、主張ごとの判定・証拠・修正案を返させる。ファイルの書き換えは親が行う。
