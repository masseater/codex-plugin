# skill-create

雛形・参照一覧・検証のような決定的な作業はスクリプトに任せ、意図の設計と本文の執筆に時間を使う。description の調整や eval を回したい場合は公式の skill-creator を使う。

## 現在の plugin

```!
${CLAUDE_SKILL_DIR}/scripts/detect-context.ts
```

## 書き方の基準

- masseater/codex-plugin リポジトリ内で作る場合は、`docs/plugin-authoring-guidelines.md` を読んでから書く。このガイドは構成要素の選び方、frontmatter、呼び出し制御、プロンプトの書き方をまとめている
- それ以外のプロジェクトでは、公式の skill ドキュメント（<https://code.claude.com/docs/en/skills>）と、そのプロジェクトの規約に従う

## 手順

1. 意図を確かめる。ユーザーの説明で足りていれば、確認だけにする
   - 何をする skill か（1 文）
   - 誰が呼ぶか: 次の 3 通りから選ぶ
     - ユーザーと Claude の両方が呼べる（既定）
     - 副作用があり、人がタイミングを決める（`disable-model-invocation: true`）
     - 背景知識なので、ユーザーが呼ぶ意味は無い（`user-invocable: false`）
   - 必要な資料: スクリプト（決定的な処理）、参照ファイル（大きい資料）、どちらも不要
2. 雛形を作る

   ```bash
   ${CLAUDE_SKILL_DIR}/scripts/scaffold.ts --plugin-dir <dir> --skill-name <name> [--scripts] [--references]
   ```

3. SKILL.md を書く
   - `description` は「何をするか」を先頭に、続けて「いつ使うか」を書く。`disable-model-invocation: true` の skill は description がモデルに見えないので、trigger は書かない
   - 事前承認したいツールは `allowed-tools` に書く（`tools` というフィールドは無い）。スクリプトは `Bash(${CLAUDE_SKILL_DIR}/scripts/<name>.ts *)` の形で、本文の実行コマンドと同じパスにする。引数なしでも呼ぶスクリプトには、引数なしの `Bash(${CLAUDE_SKILL_DIR}/scripts/<name>.ts)` も並べる
   - skill 内のファイルは `${CLAUDE_SKILL_DIR}/...`、plugin 共有の資料は `../../...` で参照する
   - 本文は 500 行未満にし、詳細は参照ファイルに分けて SKILL.md から直接リンクする
   - 読み込み時に計算できる値（設定、ファイル一覧など）は、`!` の直後にバッククォートで囲んだコマンドを書く動的注入で渡せる。この構文はコードフェンスの中でも実行されるので、構文の例を SKILL.md に書かない
4. 決定的な処理はスクリプトにする
   - `#!/usr/bin/env bun` の TypeScript で書き、`chmod +x` する
   - 結果は JSON で stdout に、エラーは stderr に出す
   - 同じディレクトリにテスト（`<name>.test.ts`。Bun 専用 API を使うなら `<name>.bun.test.ts`）を置く
   - GitHub API を呼ぶ場合は [github-api.md](references/github-api.md) に従う
5. 参照ファイルの一覧を SKILL.md に注入する。ファイルを足したり消したりしたら再実行する

   ```bash
   ${CLAUDE_SKILL_DIR}/scripts/inject-references.ts <skill-dir>
   ```

   `REFERENCES_START` 〜 `REFERENCES_END` の間は手で編集しない

6. 検証し、error が無くなるまで直す。warning は理由があれば残してよい

   ```bash
   ${CLAUDE_SKILL_DIR}/scripts/validate.ts <skill-dir>
   ```
