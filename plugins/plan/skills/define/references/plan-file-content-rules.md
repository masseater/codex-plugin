# 計画ファイルの記述規約

計画ファイルは、コンテキストがリセットされた後にこのファイルだけを渡されても実行できる文書にする。

## 自己完結させる

- 各指示は単独で意味が通るように書く。会話の履歴や以前の決定を前提にしない
- 読み手が TODO を実行するのに必要な背景（対象ファイル、制約、期待する結果）は TODO の説明に書く
- 会話の文脈がないと理解できない文は消すか、TODO の説明に書き直す

## 書かないもの

- レビューや改訂の経緯（例: 「レビュー後に修正」「指摘を受けて変更」「レビュアーの提案どおり」）
- 途中段階の案や、決定に至るまでの過程
- 検討して採らなかった案、やらないことにした作業
- 文脈に依存する参照（例: 「上で議論したとおり」「前回のとおり」「先に述べたように」）

## 改訂するとき

- 計画ファイルには最終形だけを残し、途中の版や古い決定は消す
- 読み手が「何度か改訂された」と気づかない、最初から最終形で書いたような文書にする
