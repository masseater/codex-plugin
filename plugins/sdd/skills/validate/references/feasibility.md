# feasibility: 技術詳細と実際のプロジェクト構造の照合

`specs/<spec>/technical-details.md` に書かれた内容が、このリポジトリで実際に成り立つかを確かめる。推測ではなく、実際のファイルを読んで判断する。

確かめるもの:

- 技術スタック: package.json などの依存とバージョン、tsconfig、ランタイムのバージョン指定ファイル、ビルドツールの設定
- ファイル構成: 書かれたディレクトリやファイルパスが既存の構造（ステアリングの structure.md）と合っているか
- データ: ORM のスキーマ、マイグレーション、DB 設定との整合
- インターフェース: 既存のルーティング・コントローラー・ミドルウェアとの整合
- その他、technical-details.md が言及しているすべての要素

食い違いは指摘として報告する。technical-details.md を直すのは、ユーザーが修正すると決めた後にする。直すときは次の点を守る。

- 既存の規約と構造を優先し、曖昧な記述を具体的なパス・ファイル名・ライブラリ名にする
- 新しく作るものは「新規作成」、既存を使うものは「既存を利用」と明記する
- 判断できない箇所は `**不明**` にして案を並べる
