# quality: 実装の品質

対象: Phase N のタスクが作成・変更したファイル（タスク詳細の「出力」と `git diff` から特定する）。

1. phase ファイルの「完了条件」に書かれたテスト・lint・型チェック・ビルドのコマンドを実行し、結果をそのまま記録する。書かれていなければ package.json の scripts とステアリングの tech.md から探し、それでも決められなければ `AskUserQuestion` で聞く
2. 実装したファイルごとに対応するテストがあるかを確かめる
3. ステアリング（tech.md / principles.md）に書かれたコーディング規約への違反を探し、`ファイル:行` で記録する
4. Phase 2 以降は、前の Phase の成果物との型の互換性を型チェックの結果で確かめる

コマンドの失敗は severity high、規約違反は medium として指摘する。
