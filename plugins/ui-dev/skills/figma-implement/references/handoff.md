# 実装後の引き継ぎ資料

## デザイナーへのフィードバック

実装中に見つかったデザインの問題（指摘分類 C）を、事実と影響で伝える。「なんか違う」のような印象ではなく、何が起きて誰が困るかを書く。

```markdown
## Design Feedback: <screenName>

### <問題の見出し>

- 何が問題か: <事実>
- なぜ重要か: <ユーザーへの影響>
- 提案: <解決案を 1 つ以上>
- スクリーンショット: <パス>

### 暫定対応

<暫定実装の内容。コードには `// TODO(design):` を残している>
```

## 手動 QA チェックリスト

screen map の画面ごとに確認項目を作る。対象は遷移の全経路、エラー（バリデーション・API・ネットワーク）、ホバーとフォーカス、実データでのレイアウト（長い文字列・空・大量データ）、レスポンシブ（モバイル・タブレット・デスクトップ）である。

```markdown
## QA Checklist: <flowName>

### <screenName>

- [ ] 初期表示が正しい
- [ ] <遷移先> への遷移が動く
- [ ] <バリデーション> のエラー表示が正しい
- [ ] ローディング状態が表示される
- [ ] Tab キーでフォーカスが移動する
- [ ] 長い文字列でレイアウトが崩れない
```
